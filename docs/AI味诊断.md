# 「AI 味」诊断（2026-11-18）

用户原话：「这个界面还是让人感觉一眼就是 AI 写的，包括代码也有很浓的 AI 味儿。」

这份文件不是辩解，是把「哪一眼假」逐条指出来，每条都能对着代码或截图核。分三档改法在最后，代价从低到高。

---

## 一、界面：最明显的八处

> 2026-11-18 已按 A+B 全部改掉，逐条对照见第三节「进度」。这里按原样留着，是为了留下「当时为什么这么判」的证据。

**1. 同一句话在一屏里说两遍。**
页面标题是「AdGuard Home / 把最优 IP 写进它的 DNS 重写表」，往下第一张卡片的卡头又写了一遍「AdGuard Home 把最优 IP 写进它的 DNS 重写表」（`web/static/index.html` 的 card-h）。这是生成界面最常见的产物：标题按模子套，套到已经在页面标题里说过的内容上。人会写成「连接信息」这种功能性标题，或者干脆不要这层卡头。

**2. 每张卡都是「标题 + 灰色副标题」同一个模子。**
9 张卡片、9 个卡头，其中 **7 个**都挂了灰色副标题（`<span class="sub">`），而且是清一色「把 X 做 Y」的句式（「把最优 IP 写进它的 DNS 重写」「把别人维护的 hosts 清单也写进重写」）。真实产品里副标题是可选的：有的卡有、有的没有，长度也不齐。

**3. 说明文字比字段还多。**
9 张卡里有 **28 行**灰字说明（`class="hint"`），平均每张 3 行。人写设置页的规矩是「填错会出事的地方才解释」，现在更像把设计文档搬到了界面上。比如「一行一个链接。要填列表文件本身的地址（一般以 hosts.txt 结尾），不是项目首页——填成首页会提示……」——这段话是对的，但它属于 README，不属于设置项旁边。

**4. 按钮长得跟输入框一样。**
`.btn.sm`（「看看现在写了哪几条」）是白底、1px 边框、小圆角，跟它上面那个 input 视觉同源。截图里第一眼看过去像一个空着的文本框，而不是能点的按钮。这是没给按钮做「可点」的视觉层，直接复用了表单的皮肤。

**5. 拿现成组件硬套，再用内联样式把边角压掉。**
```html
<div class="hero-actions" style="border-top:none;padding-top:0;margin-top:0">
```
`hero-actions` 是给页面顶部那排操作按钮用的（带上方分隔线），这里靠三行内联样式把边框和内边距压掉塞进卡片中间。这种「借一个差不多的 class，再覆盖掉它的特征」是非常典型的生成痕迹；人改过两次就会直接新起一个 class。

**6. 并排的两个字段宽度不等。**
用户名 / 密码在一行里，两列不等宽（网格列宽按内容走），填进去以后左右边界对不齐。人写两列要么等宽，要么竖排。

**7. 视觉参数全是模板默认值。**
18px 圆角、`0 8px 24px -12px` 的柔光阴影、`#3b5bdb` 那种偏亮的蓝、iOS 风格开关、登录页顶部一层径向渐变光晕（`.login` 的 `radial-gradient`）。单看每一样都不难看，凑在一起就是「shadcn / Tailwind 默认审美」。Tools 类产品的样子通常更硬：圆角小、阴影几乎没有、靠分隔线和留白分层。

**8. 导航骨架也撞脸。**
左侧「工作台 / 系统」两个分组 + 底部一个「● 服务运行中 开发版」状态点。这套骨架几乎和任何一个 AI 生成的 dashboard 一模一样，跟这个应用「一个人自己用」的定位也不匹配——它不需要分组成体系，需要的是「五个页面一眼看完」。

## 二、代码：五处文风指纹

**1. 注释密度太高，且高在「解释」而不是「约束」。**

| 文件 | 总行 | 注释行 | 占比 |
|---|---|---|---|
| `config/config.go` | 620 | 242 | **39%** |
| `web/hosts.go` | 399 | 111 | 28% |
| `web/server.go` | 1924 | 505 | 26% |
| `web/domains.go` | 398 | 85 | 21% |

长期维护的 Go 项目通常 10% 上下，且注释多为「这个字段必须是 X」「别在这里改，因为 Y」这类约束。现在大量是「当初为什么这么设计」的叙述，读起来像设计文档的碎片。

**2. 301 处「——」出现在 Go 注释里。**
这是最硬的文风指纹。人写中文注释多用句号、逗号、括号；「先下一个判断、再用破折号补一个转折」是生成文本的惯性句式，一段里出现两三次就露馅了。搜一下就看得出来：
```bash
grep -c "——" web/*.go config/*.go
```

**3. 每个函数都是同一个三段式。**
「先讲背景 → 再讲取舍 → 最后讲后果」，连 `resolveHosts` 这种直接了当的函数也写了九行头注释。真实的代码库里注释是**不均匀**的：简单的函数一行没有，踩过坑的地方密密麻麻。均匀本身就是破绽。

**4. 为了少一个 import 手写标准库。**
```go
// 只用来拼一两处日志，不值得为它引 strconv 的语义噪音。
func itoa(n int) string { ... }
```
这种「自己实现一遍 `strconv.Itoa`」的偏好很常见于生成代码。久维护的项目会直接 `strconv.Itoa`，嫌长就 `fmt.Sprint`。

**5. 所有分支的防御密度一样齐。**
几乎每个错误分支都有日志、有兜底、有面向用户的措辞，一个不漏。人会漏（并在别处留下补救痕迹），会在真正出过事的地方加密、别处从简。整齐到没有一丝松弛，反而不像人写的。

另外，命名也整齐得可疑：`friendlyErr` / `plausibleHostname` / `hostsWantFor` / `looksLikeHTML` —— 每个都恰到好处地长，没有一个是「当初随手起的、后来懒得改」的名字。

**C 实际改了什么**（32 个 `.go` 文件，+779 / −1385 行；注释行 3899 → 3304，全仓密度 17% → 15%）：

- **`itoa` 全部删掉**，四个文件（`domains.go` / `hosts.go` / `switch.go` / `server.go`）共 14 处改回 `strconv.Itoa`。那个手写函数本来就是为了少一个 import，自己反倒带了 14 行注释。
- **注释里的 `——` 清掉**：30 个文件 240 行，按「表格式对齐的改冒号、其余改逗号」批量替换，再清掉 16 行替换出来的多余空格。代码和字符串里的原样留着。
- **每条注释只留「为什么」，不留「这是什么」**：函数名已经说清楚的事不再复述。典型是 `config/config.go`（39% → 28%）和 `ddns/provider.go`（38% → 29%）的字段说明，从「三段式：是什么 + 为什么 + 举例」压成一段。
- **一段话最多四行**。删掉的是那类「先总述、再分点、最后再总结一遍」的结构，比如 `main.go` 里 27 行的升级恢复说明压到 6 行（保留两条真踩过的坑：2026-11-17 数据目录被删/换位置、v1.6.5 删掉 `MigrateFromLegacyData` 的理由）。
- **保留全部踩坑记录**：`cp -p` 搬属主、闪退静默、`1fr` 不等宽、`.field:last-child` 削错、滑块轨道同色、认领语义、`#US` 是占位标签、两个国家开关键名反着来。这些正是「人写的注释」和「AI 凑字」的区别，一条都没删。
- **顺手修掉两处被批量替换弄歪的地方**：`ipv6/local.go`、`ipv6/local_test.go` 的字段对齐被打乱，重跑了 `gofmt`。`gofmt -l` 现在仍然只报那三个既有文件（`web/ipv6_test.go`、`web/switch_test.go`、`config/location.go`）。

**没到 10%**：留下的是 15%，单文件最高 29%（`ddns/provider.go`、`config/config.go`、`web/cfcheck.go`）。再往下砍就得删「为什么这么写」的句子，那些句子是这张表第一节批评的反面。要继续压，得先决定「宁可少知道一点」还是「宁可多读两行」。

## 四、不做什么

- **不为「像人」而故意写差**：不加无意义缩写、不删记录真实坑的注释、不制造前后不一致。那种「装作人类」比 AI 味更糟。
- **不重写架构**。外观与注释是表层，改它们不该动到测试、行为和已经真机验过的逻辑。
- **不在这轮加功能**。用户 2026-11-18 已定：新功能开发到此结束，先使用观察。
