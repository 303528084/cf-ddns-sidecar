## 二、定下来就不能随口改的三件事

这三条是 2026-11-17 逐条确认过的，改动需要重新确认。

1. **完成标准 = 保存即生效**。不要求用户「保存完再手动去停止启动一次」。
   这条直接决定了实现方式：密码必须每次登录现读，端口必须由程序自己监视并重启。
2. **`third_party/cfnb/main.py` 只许改注入配置**。想改它的测速逻辑，必须先停下来问。
3. **能力白名单留空**。白名单只能收紧，不能自行放宽；要越界先说明需要什么、为什么、不用的代价。

## 四、待定

已定：装依赖=先报清单；公网=要部署（见卡片）。

**公网部署方案尚未提出。** 按规则，涉及公网暴露必须先出方案、经你同意才能动手，所以现在什么都没做。需要先定的点：

1. 怎么暴露：自己用反代（如 Caddy / Nginx / Cloudflare Tunnel）加 HTTPS，还是只靠端口映射。
2. 访问控制：现在只有一道登录密码，且后台对所有 IP 开放。要不要加限制（如固定只允许某几个 IP、或加一道 Basic Auth）。
3. 证书：用域名 + Let's Encrypt 自动续期，还是别的办法。

现状风险（未解决，先记着）：后台走明文 HTTP，密码在数据目录里以明文文件存放；一旦直接暴露到公网，密码可能在传输中被截获，也会持续遭遇暴力尝试。
