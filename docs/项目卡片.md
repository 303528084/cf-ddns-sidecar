## 二、定下来就不能随口改的三件事

这三条是 2026-11-17 逐条确认过的，改动需要重新确认。

1. **完成标准 = 保存即生效**。不要求用户「保存完再手动去停止启动一次」。
   这条直接决定了实现方式：密码必须每次登录现读，端口必须由程序自己监视并重启。
2. **`third_party/cfnb/main.py` 只许改注入配置**。想改它的测速逻辑，必须先停下来问。
3. **能力白名单留空**。白名单只能收紧，不能自行放宽；要越界先说明需要什么、为什么、不用的代价。

## 三、当前状态（每次阶段结束更新）

> 只写**现在成立**的事实。v1.4.x 交付细节、v1.0.0~v1.4.1 逐版验收史已移到 `docs/变更记录.md`。

- **AdGuard 写入改成「只动自己认领的域名」（2026-11-18 本地已改完、未发版；提交 `f35b390`）**。
  原来 `ReplaceRewrites` 是「清空整张重写表、再按 want 全量重建」，两个毛病：① 用户在 AdGuard 后台
  自己加的、或别的工具写的重写规则，**每轮测速都被一起删掉**，而界面只说「已写入 AdGuard：N 条」；
  ② 删光与重建之间有一段窗口重写表是空的，家里设备来查域名会拿不到重写结果。现在按差异收敛：
  `want` 的**键**就是「这域名归本工具管」的声明，不在里面的域名一条都不碰；`want[d]` 里没有的答案才删、
  缺的才补、已对上的原样不动。停用过（`enabled:false`）的记录算「不一致」，删了重写成启用——否则会出现
  「记录在、但不生效」这种界面完全看不出来的坏状态。
  **规则上必须堵的那个口子（用户 2026-11-18 选的「一起清掉」）**：用户从域名列表里删掉 `a.com` 之后，
  `a.com` 就不在 `want` 里了，程序再没理由碰它 → AdGuard 上会留下一条指向旧 IP 的永久残留，界面看不出来。
  为此 `config.Config` 新增账本 **`RewrittenDomains`**（本工具认领过哪些域名），两处调用点统一走
  `rewritePlan`（当前列表 + 已失管域名给空答案集）与 `rememberRewritten`（落盘，内容没变不写盘）。
  **没有答案（还没测出 IP）时绝不带清理项**，否则会变成「把所有域名下的记录都删掉」。
  连带修掉两处：`handleImport` 缺 `PruneDomainMeta()` 已在上一条修过；**预览接口原来只拿 v4 的 IP 比答案，
  v6 那条明明会保留却被标成「会被清掉」**——现在 `/api/adguard/rewrites` 返回 `managed`（域名→答案列表，
  v4/v6 各一条）+ `stale`（已失管将被清掉），界面标三种状态：保留 / 会被改掉 / **不归这个程序管**（灰色，
  不上黄底）。账本跟着备份走（`bundleConfig.rewritten_domains`，导入侧归一化 + 上限 200 条，不进
  restored/kept 两本账——它不是用户设的项）。
  **本地验过**：`go test ./...` 全绿（新增 `dns/adguard_test.go` 五条 + `web/rewrite_test.go` 两条 +
  `TestCloneCopiesRewrittenDomains`）；容器里接一个假 AdGuard（`.scratch/fake_adguard.py`，预置四条记录），
  真实界面点「看看现在写了哪几条」得到四种标记，删掉 `a.com` 后假服务收到的请求是
  **DELETE a.com×2 / DELETE dropped.com×1 / ADD b.com×2**，`my-printer.lan` 一条都没碰；
  1440 / 390 两个宽度都看过，390 横向溢出 0 px。脚本 `.scratch/ag_check.py`。
  **一个无法区分的情况（已在界面说明）**：同一域名下用户自己也加了一条重写，那条会被覆盖——AdGuard 的
  重写记录里没有「谁写的」字段，只能按「域名归谁管」划分地盘。
