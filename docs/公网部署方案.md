## 一、先说结论

**推荐组合：Cloudflare Tunnel + Cloudflare Access + 代码侧 2 项必改 + 3 项建议改。**

理由一句话：你已经有域名、已经在用 Cloudflare（DDNS 用的就是它），再走 Tunnel 不用新买任何东西，
而且它**不需要在路由器上开端口**——NAS 根本不出现在公网上，被全球扫描器扫到的机会归零。

下面把「为什么」摊开讲，最后列需要你拍板的三件事。

## 二、现状：代码里到底是什么样（我逐个文件看过的，不是推测）

| 项目 | 现状 | 意味着什么 |
|---|---|---|
| 监听地址 | `:端口`，绑定**所有网卡** | 路由器一旦做端口映射，全世界都能连 |
| 进门凭证 | **只有一个密码** | 密码就是唯一的墙。密码弱 = 墙等于没有 |
| 密码怎么比 | 恒定时间比较 + 失败时**故意等 0.5 秒** | 防住了「靠响应快慢猜密码」，但**没有次数限制、没有锁定** |
| 密码怎么存 | `dashboard-password` 文件，**明文**，权限 0644 | 能读这个目录的人/程序都能看到密码 |
| 密钥怎么存 | `ddns.env`，**明文**，0644 | 同上，各家 DNS 的 API 密钥都在里面 |
| 登录后凭证 | 签名令牌，有效期 **30 天** | 拿到一次就能用一个月（改密码会立刻全部失效，这点是好的） |
| Cookie 属性 | `HttpOnly` + `SameSite=Lax`，**没有 `Secure`** | 因为是 HTTP，`Secure` 加了 Cookie 就不发了；换成 HTTPS 后必须补上 |
| 传输加密 | **没有 HTTPS** | 密码在网络上明文传输，同一 Wi-Fi 下可被嗅探 |
| 安全响应头 | 没有 | 缺 CSP / Referrer-Policy；**但不能随便加 `X-Frame-Options`**，见下面第 4 条 |

### 三个我特别要提醒的发现

**1. 登录没有「试错次数」限制**

现在每次密码错误只等 0.5 秒。看起来慢，但如果用脚本同时发 20 个请求，一秒就能试 40 次。
密码要是 `Test123456` 这种，几分钟就破了。**这是暴露到公网前最该堵的口子。**

**2. `/api/candidates` 有个「本机免登录」的口子**

代码里写着：来自 `127.0.0.1` 的请求不需要登录就能访问。**一旦你在前面加了反向代理，
所有公网请求在程序眼里都变成了「来自 127.0.0.1」**——这个口子就对全世界敞开了。
它泄露的是 Cloudflare 候选 IP 列表（公开信息，后果不严重），但性质是「未登录可访问的接口」，
必须堵。

**3. 别加 `X-Frame-Options` 头**

飞牛桌面是用 **iframe 嵌入**打开后台的。如果加上 `X-Frame-Options: DENY/SAMEORIGIN`，
今天刚修好的桌面图标会立刻变白屏。将来做安全加固时这条要绕开，我个人建议直接不碰这个头。

**4. 桌面图标和公网访问是两条独立的路**

- **局域网**：点飞牛图标 → `http://10.10.10.250:9090`（直连，明文，但在你家内网）
- **公网**：浏览器输域名 → 经过 Cloudflare → 到 NAS

加了 Tunnel 之后，局域网这条路**依然存在**（程序还是监听所有网卡）。
所以「公网怎么进」和「家里怎么用」要分开考虑，别指望一个改动解决两件事。

## 三、风险清单（按后果从重到轻）

| # | 风险 | 后果 | 现在能防住吗 |
|---|---|---|---|
| 1 | 密码被暴力破解 | 攻击者拿到后台 → 改你的 DNS 解析、读走各家 API 密钥 | ❌ 没有次数限制 |
| 2 | 明文 HTTP 传输密码 | 同一网络下被嗅探；公司/咖啡厅 Wi-Fi 尤其危险 | ❌ 没有 HTTPS |
| 3 | NAS 公网 IP 暴露 | 被全网扫描器盯上，持续尝试各种漏洞 | 取决于怎么暴露 |
| 4 | 密码/密钥明文存盘 | 一旦 NAS 被入侵，这些直接是明文 | ⚠️ 靠文件权限挡 |
| 5 | 令牌 30 天有效期 | 电脑被偷/浏览器数据泄露，一个月内都能进 | ⚠️ 改密码可全部作废 |

## 四、三条路，你选一条

### 路 A：Cloudflare Tunnel（推荐）

**怎么工作**：NAS 上跑一个叫 `cloudflared` 的小程序，它**主动往外连** Cloudflare。
你访问 `https://cf.你的域名.com` 时，请求先到 Cloudflare，再顺着这条已经建好的隧道送到 NAS。
**NAS 一个端口都不用对公网开。**

**优点**
- 路由器不用做端口映射，NAS 的公网 IP 完全不暴露（扫描器根本找不到你）
- HTTPS 自动就有（Cloudflare 的边缘证书），不用申请、不用续期
- 可以直接叠加 **Cloudflare Access**：在 Cloudflare 那边再加一道「先登录才放行」，
  支持邮箱验证码 / Google 账号。等于**两把锁**
- 免费额度够个人用（Access 免费版 50 个用户）

**代价**
- 多一个进程（一个 Docker 容器）。这会打破项目现在「一个容器搞定一切」的设计，
  所以我的建议是：**它不打包进 `.fpk`**，而是作为「可选附加件」，你想要就自己加一个容器
- 依赖 Cloudflare。Cloudflare 挂了，公网就进不去（局域网直连不受影响）
- 访问多绕一跳，延迟增加几十毫秒
- 需要域名托管在 Cloudflare（你的应该已经是了，因为 DDNS 走 CF API）

---

### 路 B：反代 + 路由器端口映射

**怎么工作**：NAS 上跑 Caddy 或 Nginx 做反向代理，路由器把 443 端口映射到 NAS，
域名解析到你的公网 IP（动态 IP 要靠 DDNS，你已经有能力了）。

**优点**
- 不依赖第三方，通透、可控
- Caddy 能自动申请和续期 Let's Encrypt 证书，配起来比 Nginx 简单
- 延迟最低

**代价**
- **必须在路由器上开端口**，NAS 的 IP 从此在公网上「有名有姓」，会被持续扫描
- 家宽的公网 IP 可能是运营商 NAT 的（没有真公网 IP 就做不了），要先确认
- 证书续期依赖 80/443 可达，一旦路由器规则出错，证书会悄悄过期
- 前面加反代后，上面说的「本机免登录」口子必须同步修掉

---

### 路 C：只给局域网 + VPN

**怎么工作**：后台完全不上公网。你在外面要看，先连 WireGuard / Tailscale 回家。

**优点**
- 安全性最高：攻击面约等于零，密码再弱也没人能试
- 不用改任何代码
- Tailscale 配置简单，手机装个 App 就行

**代价**
- 每次在外网访问都要先连 VPN（多一步操作）
- **不适合「分享给别人用」**：给朋友开 VPN 账号比给个网址麻烦得多
- 手机端要装客户端

---

### 三条路对比

| | 路 A Tunnel | 路 B 反代 | 路 C VPN |
|---|---|---|---|
| NAS 暴露公网 IP | ❌ 不暴露 | ✅ 暴露 | ❌ 不暴露 |
| 要开路由器端口 | ❌ 不用 | ✅ 必须 | ❌ 不用 |
| HTTPS | 自带 | Caddy 自动申请 | 不适用 |
| 额外一道锁 | ✅ 可加 Access | ⚠️ 只能加 Basic Auth | ✅ VPN 本身就是锁 |
| 分享给别人用 | ✅ 容易（发链接） | ✅ 容易 | ❌ 麻烦 |
| 依赖第三方 | Cloudflare | 无 | Tailscale |
| 新增进程 | 1 个容器 | 1 个容器 | 1 个客户端 |
| 适合你吗 | **最贴合** | 有真公网 IP 才行 | 只自己用的话 |

## 五、推荐组合的落地步骤（**你同意后我才开始**）

**第 0 步 · 你先做（不用我）**
1. 确认域名托管在 Cloudflare（后台里能改 DNS 记录就是）
2. 想一个强密码（20 位随机），别用 `Test123456`

**第 1 步 · 代码加固（我来做，1 个提交）**
- 登录失败限流：同一 IP 连续失败 5 次 → 锁 5 分钟，之后指数退避
- 堵掉 `/api/candidates` 的本机免登录口子
- Cookie 补 `Secure`（仅在识别到 HTTPS 时）
- 安全响应头：CSP、Referrer-Policy（**不加 X-Frame-Options**）

**第 2 步 · 你去 Cloudflare 建 Tunnel（我给图文步骤）**
- Zero Trust → Tunnels → 新建 → 装 `cloudflared` 容器 → 配一个子域名指到 `http://NAS内网IP:9090`

**第 3 步 · 加 Access 策略（我带你配）**
- 只允许你的邮箱能进 → 等于「Cloudflare 先验一次身份，NAS 再验一次密码」

**第 4 步 · 验收**
- 外网用手机流量访问域名 → 应该先看到 Cloudflare 的登录页 → 通过后再看到我们的后台
- 局域网图标照旧能用

## 六、要改的代码，分「必改」和「建议」

### 必改（不修就有真风险）

| 改什么 | 为什么非改不可 |
|---|---|
| 登录失败限流 | 没有它，公网暴露等于把密码交给暴力破解 |
| 堵 `/api/candidates` 的本机免登录 | 加了反代/Tunnel 后，这个口子对所有人生效 |

### 建议改（提升但不紧急）

| 改什么 | 收益 | 代价 |
|---|---|---|
| Cookie 加 `Secure` | 防止令牌在明文连接上泄露 | 只在 HTTPS 下有用，HTTP 下要自动跳过 |
| CSP / Referrer-Policy | 减少 XSS 和 Referrer 泄露 | 要小心别写坏 iframe（不能加 frame-ancestors 限制） |
| 密码改哈希存储 | 文件被读走也拿不到明文密码 | **会失去「忘记密码时能去文件里查」这个便利**，我不建议这轮做 |
