# Cloudflare 优选 IP + AdGuard Home + DDNS（飞牛 fnOS）

在飞牛 NAS 上一键搞定三件事：**测出你家网络最快、真能连上的 Cloudflare 节点**，
把它写进 **AdGuard Home** 的 DNS 重写，同时更新你**自有域名的解析记录**。
一个容器、一个后台界面，装完点几下鼠标就能用。

## 它能干什么

| 能力 | 说明 |
|---|---|
| 优选 IP | 从 Cloudflare 官方地址段随机采样 + 多源聚合，先 TCP 筛延迟，再做**反代验证**（确认这个 IP 真能承载 HTTPS 请求），最后跑真实带宽，排出最优 |
| 写 AdGuard | 把最优 IP 写进 AdGuard Home 的 DNS 重写表，局域网设备自动走这条线路 |
| DDNS | 把最优 IP 写到你自有域名的 A 记录，支持 Cloudflare / 阿里云 / 腾讯云 DNSPod / 华为云；只写最快的那条，或者按排名一次写前 N 条（条数自己定） |
| 统一后台 | 一个界面管全部：状态、AdGuard、要加速的域名、测速参数、域名解析密钥、实时日志 |
| 出问题看得见 | 运行日志落盘 `app.log`（重启回填）、显示下次测速时间与上次成败、失败自动重试一次、能看到 AdGuard 当前重写表里哪几条会被下次测速清掉 |
| 能自助排查 | 「测试密钥」只读校验（不动你的解析）、「立即更新一次」立刻生效不用等周期 |
| 配置可带走 | 「导出配置文件」存成 json，重装 / 换 NAS / 数据目录被清空时上传恢复 |
| 自己守门 | 后台可改登录密码并拦弱密码、登录失败限流、配置被自动恢复时界面挂红条 |

## 为什么测速换了引擎

早期的实现用的是「TCP 延迟 + 下载测速」，选出来的 IP 经常**TCP 能连、浏览器打不开**。
现在改用 [xinyitang3/cfnb](https://github.com/xinyitang3/cfnb) 的测速引擎，
它多了一道**反代验证**（对每个候选 IP 发真实 HTTPS 请求、验证 TLS 与响应，多轮采集延迟和抖动），
能剔掉「通但不可用」的节点。

同时我们加了一层保底：**内置 Cloudflare 官方地址段快照**，在本地随机采样生成候选，
所以即使所有第三方数据源都挂了，测速依然能跑出结果，不会卡在「拉不到节点」。

## 关于代理

**测速必须直连，不能走代理。** 原因很简单：测的是「你家宽带 → Cloudflare 边缘」这条路的快慢，
走代理测出来的是代理服务器的线路，对你没用。

本程序已经强制直连（给测速引擎设了 `FORCE_DIRECT`，会清掉所有 `*_PROXY` 变量）。所以：

- 你在**电脑上**开代理 → 不影响 NAS 里的测速；
- 你在**NAS 上**设置了全局代理环境变量 → 也会被清掉，不影响；
- 但如果你的**路由器**做了全局透明代理（所有流量强制走代理），测速结果就会失真，
  这种情况需要给 NAS 单独放行直连。

## 安装（飞牛 fnOS）

1. 到本仓库 **Releases** 下载 `cf-ddns-sidecar-<版本>.fpk`；
2. 飞牛桌面 → **应用中心** → 右上角 **设置** → **手动安装应用** → 选择该文件；
3. 装完桌面会出现「优选IP DDNS」图标，点开即是后台（也可以浏览器访问 `http://飞牛IP:端口`，端口默认 8080）。

**安装过程中会弹出一页「后台访问」向导**，只问两件事：

1. **后台端口** —— 留空 = 默认 `8080`；
2. **登录密码** —— 留空的话程序自动生成一个，打印在
   「应用中心 → 本应用 → 运行日志」里，也能在数据目录的 `dashboard-password` 文件里看到。

后台**对所有 IP 开放**（不做来源网段限制），所以密码务必设置。

> **为什么向导只有这两项**：飞牛的向导输入框不会回显已保存的值。如果把域名、
> 服务商这些「有内容」的项也做成表单项，你哪怕只想改个密码、其余不动地保存一次，
> 它们也会被覆盖成表单里的默认值（比如服务商被切回 Cloudflare，DDNS 直接断掉）。
> 所以带内容的配置统一放后台界面里改，那里显示的是当前真实值。

> **什么时候会弹向导**：只有「**全新安装**」才弹。已经装过再覆盖升级（点更新）不弹，
> 因为升级不该打断你——升级想改端口/密码就走「应用设置」，那份表单和安装向导是同一套字段。

**后台端口**默认 `8080`，和 NAS 上别的服务撞端口时才需要改（1024-65535）。
改端口后桌面图标会跟着走：入口配置里写的是占位符，飞牛生成图标地址时自动填成
你设定的端口；更老的飞牛版本则由程序启动时兜底纠正一次。不需要卸载重装。

**装完之后想改端口或密码**：「应用中心 → 本应用 → 设置」。⚠️ 两项都留空直接点保存
= 什么都不改，可以放心点。

保存后**立刻生效，不用手动重启**：密码是每次登录时现读的；端口变了程序会自己
发现并重启（约 15 秒内），不必依赖「应用设置」去重启容器。

## 配置（全在后台界面里）

打开后台，从上往下填：

1. **AdGuard Home**：地址（`http://192.168.1.2:3000`）+ 用户名 + 密码；
2. **要加速的域名**：点「+ 添加域名」，填套了 Cloudflare 的网站域名（如 `openai.com`）；
3. **测速设置**：自动测速间隔（默认 60 分钟，填 0 表示只在手动点时才测）；
4. **域名解析（DDNS）**：勾上启用 → 选服务商 → 填优选域名 → 填密钥 → 填「同步几条 IP」；
5. 点「保存全部设置」，再点「立即测速」。

密钥留空表示「不修改已保存的值」，所以改域名时不用重新填一遍密钥。

**同步几条 IP**：按测速排名从优到劣取前 N 条写进 A 记录，1–20 之间，默认 1（跟以前一样，只写最快那条）。

这个设置是**「对齐」而不是「追加」**：填几条，这个域名下就只留几条。域名里原来那些同名 A 记录（包括你自己以前手工加的）会被删掉，否则会一直留着已经失效的旧 IP。测不出 IP 的时候一条都不会删——那时候程序什么都不做。

顺带说个容易踩的点：一个域名有多条 A 记录时，访问者**不是「都用最快那条」，而是随机挑一条**。所以 2～3 条是「一条挂了还有备胎」，填到 5 条以上，大部分访问反而会落到不是最快的那些上面。真想让所有人都走最快的，就填 1。

改了条数不用重新测速：点「立即更新一次」会拿上次测速的完整排名去补齐或收回（排名存在配置里，不只是存写进去的那几条）。

**记录缓存时间（TTL）**：留 0 就是用各家默认值（Cloudflare 自动、DNSPod 600、华为云 300、阿里云账号默认）。填了之后，改了 IP 别人要等这么久才拿到新的——想「换了马上生效」可以填 600，但填太小有些免费版会直接拒绝（阿里云免费版要求 ≥600）。允许范围 60–86400。

**Cloudflare 云朵（代理）开关**：默认关闭，**建议保持关闭**。开了之后域名会解析到 Cloudflare 的节点，不再指向你测出来的优选 IP，DDNS 就白做了——只有在你更想隐藏源站、并且不需要优选 IP 的时候才开。开了之后日志里会留一行提示，方便以后解释「为什么解析出来的 IP 不是我选的那个」。

**填完密钥怕填错？** 点域名解析卡片里的「测试密钥」。它只读：确认密钥能用、能查到这个域名、现在指向哪个 IP，**不会改动你的解析**。注意它测的是**已保存**的值，刚改完要先点「保存全部设置」。确实要立刻把当前最优 IP 推上去，再用旁边的「立即更新一次」（那个会真的改 A 记录）。

**想知道到底写进 AdGuard 了什么？** AdGuard 卡片里的「看看现在写了哪几条」会列出它当前的重写表原文，并标出哪几条是下次测速后保留的、哪几条会被清掉。**每次测速都是「清空整张表再重建」**，所以你手工加在 AdGuard 里的其他重写记录也会被清掉——这就是提前看一眼的理由。

最上面的「当前状态」里有**下次测速**（间隔填 0 则显示「未开启」）和**上次结果**（成功 / 失败 / 还没跑过，连续失败还会显示次数）。测速跑失败会自动重试一次（等 10 秒），日志里会写「N 秒后自动重试一次」和「开始重试」。

最下面的**登录密码**用来改后台密码：填当前密码 + 新密码两遍即可，当场生效、不用重启（也可以继续用「应用设置」改，两者等价；但「应用设置」里填什么都不校验，这里会拦下 `12345678` 这类弱密码）。

数据目录（**v1.4.0 起**：飞牛「文件管理」→ 存储空间根目录下的 `cf-ddns-sidecar-data` 文件夹）：
`config.json`（配置与状态）、`config.json.bak`（上一次写入前的备份）、`ddns.env`（密钥）、`dashboard-password`（后台密码）、`app.log`（运行日志，超过 2MB 自动轮转为 `app.log.1`）。

> 老版本（v1.3.2 及更早）在「文件管理 → `cf-ddns-sidecar` → `data`」。第一次装 v1.4.0 时会自动把里面的东西搬到新位置，四个配置文件一个都不落。容器里看到的路径始终是 `/app/data`，程序不用关心它实际在哪。

**备份**：后台最下面的「备份与恢复」→「导出配置文件」，会下载一个 `.json`（里面连密钥一起带上了）。重装、换一台 NAS、或者哪天数据目录又被清空，在同一处点「从文件恢复」上传那个文件即可。文件里是明文密码和密钥，请当密码一样保管。

**升级不丢配置（v1.3.1 起，v1.3.2 和 v1.4.0 各加固一层）**：`config.json`、`ddns.env`、`dashboard-password`、`.wizard-env-applied` 会被备份成 `<时间>` 子目录，只保留最近 3 份。备份位置搬过三次，每次都是同一个原因——**备份不能放在会被删的那一层里**：

| 版本 | 备份放在哪 | 为什么不够 |
|---|---|---|
| v1.1.1 | `share/cf-ddns-sidecar-backup-<时间>/` | 在应用目录**里面**，整层被删跟着没 |
| v1.3.1 | `/var/apps/cf-ddns-sidecar-backup/`（应用目录的**兄弟**） | 仍在 `/var/apps` 下，整个清空就没了 |
| v1.3.2 | 同上的路径，但它是**指向存储卷**的符号链接，实际落在 `/vol1/cf-ddns-sidecar-backup/` | 卷根下的目录属于用户，不归应用管 |

容器里看到的路径始终是 `/app/backup`，程序不用关心它到底在哪。这个符号链接由安装脚本在每次启动时安置（找不到存储卷就老老实实用真实目录，不会因此起不来）。

**正本也搬了一次（v1.4.0）**。上面那张表搬的全是**备份**，数据本身一直留在 `/var/apps/cf-ddns-sidecar/share/cf-ddns-sidecar/data`——而飞牛升级时删的正是 `/var/apps/cf-ddns-sidecar` 这一整层。于是「每次升级都要拿备份把配置捡回来」成了固定流程，这本来就不该发生。v1.4.0 起正本同样放到存储卷根下（`/vol1/cf-ddns-sidecar-data`），`/var/apps/cf-ddns-sidecar-data` 只是指向它的快捷方式。一句话：**备份是出事之后的补救，把正本放到平台不认识的地方才是根治。**

备份有**两个来源**，任意一个成立就够用：

- **程序自己备的（v1.3.2 起）**：你在后台点一次「保存全部设置」，程序就地在备份目录里留一份。不依赖飞牛的任何脚本，所以最可靠；
- **升级开始时备的（v1.3.1 起）**：宿主机脚本在覆盖升级前再备一份，覆盖「装完之后一次都没保存过」的情况。

装完之后，如果程序发现数据目录是空的、而备份还在，会**自己把配置搬回来**，并在后台顶上挂一条红条，写清「从哪个备份捡回来的」。核对无误点一次「保存全部设置」红条才会消失。

几条边界说清楚：

- **只在真的空了的时候动手**。数据目录里已经有 `config.json`（或 `config.json.bak`）就一条都不碰，不会拿旧备份盖掉你现在的东西；
- **内容没变就不重复备份**。测速每跑一次都会改 `config.json` 里的「上次最优 IP」，如果每次都备一份，3 份历史几分钟就被刷光，真出事时只能捡回「三分钟前」。所以只有配置真的变了才新增一份；
- 恢复回来的内容是**备份那一刻**的样子，之后你在后台改过的东西自然不在里面——所以顶上那条红条值得认真核对一遍；
- 程序一启动就会在运行日志里写一行「备份目录 … 可用：共 N 份，最新 <时间>」。如果写的是「不存在」或「写不进去」，说明备份这条路没通，请把那一行发我。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 测速报「没有产出可用 IP」 | 极少见（已内置官方段保底）。若出现，多半是 NAS 完全没有外网出口，检查网络 |
| 写了 AdGuard 但设备还是走老 IP | AdGuard 客户端缓存。在该设备上重连网络，或在 AdGuard 里清一下缓存 |
| 域名解析报 403 / 401 | 密钥权限不足。Cloudflare 令牌需要「编辑区域 DNS」权限，Zone ID 要填对 |
| 后台打不开 | ① 确认用的是设过的端口（默认 8080）；② 端口被 NAS 上别的服务占了，换一个再保存 |
| 忘了后台密码 | 「应用中心 → 本应用 → 设置」里重设一个，保存即生效（不用等重启） |
| 安装时没看到向导，直接就装完了 | ① 只有全新安装才弹，覆盖升级不弹；② 早期发过的包可能缺 `wizard/install`，换最新版并**先彻底卸载**再装 |
| 安装时设的端口/密码没生效 | 早期版本有此问题：容器先起来了，脚本却没权限重启它。升级到最新版后**到「应用设置」把端口和密码再填一次保存**即可，立即可生效 |
| 还是没生效，怎么自己判断原因 | 打开「应用中心 → 本应用 → 运行日志」，往下找 `[诊断]` 开头的几行。它是安装/设置时填的值在那一刻**到底有没有送到**的记录：① 显示 `wizard_port = <空>` → 值没送到，属飞牛平台问题，请在「应用设置」里再存一次（这条路径走的是文件，不依赖平台传值）；② 显示 `wizard_port = <4 位>` 但上面「后台地址」还是旧端口 → 送到了但没写进文件，多半是权限问题，请把运行日志贴给我 |
| 点桌面图标提示「拒绝了我们的连接请求」，浏览器却能打开后台 | 图标的端口和程序实际端口不一致。v1.0.1 已修（入口改用占位符自动跟随）。若仍出现：重启一次应用让启动脚本纠正；或用浏览器能打开的那个端口进去，在「应用设置」里把端口再存一次 |
| 改端口后图标点不开 | 保存后约 15 秒程序会自己按新端口重启；若图标仍指旧端口，关掉应用中心页面重新打开即可 |
| 卸载后想彻底清干净 | **v1.1.1 起卸载不再删数据**（这是刻意的：以前自动删，导致「升级」时把配置一起删了）。想清干净，去「文件管理」的存储空间根目录删掉这两样：`cf-ddns-sidecar-data`（配置、密钥、日志）、`cf-ddns-sidecar-backup`（备份）。**v1.3.2 及更早装过的还要多删一个 `cf-ddns-sidecar` 共享文件夹**——老版本的数据在里面 |
| 升级后后台里的设置全变回默认值 | **v1.4.0 起这条路被堵死了**：数据本身放在存储卷根下的 `cf-ddns-sidecar-data`，飞牛升级时删的是 `/var/apps/<应用名>` 那一层，够不到它。v1.3.2 及更早只能靠「备份 + 装完自动恢复」补救（正本在 `/var/apps` 里，一定会被删）——那套机制仍然保留，作为最后一道保险。v1.1.0 及更早被清空的配置找不回来，只能重新填 |
| 想放到公网访问（不在家也能打开后台） | 推荐 Cloudflare Tunnel + Cloudflare Access，**不要在路由器上开端口映射**。v1.1.0 起代码侧已加固（登录失败限流、堵住「本机免登录」口子、安全响应头），方案见 `docs/公网部署方案.md`。注意必须先把管理密码改成强密码 |
| 输错几次密码后提示「次数过多，请 xxx 秒后再试」 | 这是 v1.1.0 起的登录限流：同一来源连错 5 次锁 5 分钟，之后每轮翻倍、最长 1 小时。等待即可，或换个网络重试。登录成功会立刻解锁 |
| 想改后台密码 | 在后台页面下方的**登录密码**卡片里改：填当前密码 + 新密码两遍，当场生效、不用重启。改的时候要求至少 8 位，不能是 `12345678`、`abcdefgh`、`aaaaaaaa`，也不能是 `password`、`admin123` 这类最常见的弱密码。**注意：v1.3.2 起页面不会再对现有密码的强弱做任何提示**——安装时设了几位就是几位，不会每次打开页面提醒你换 |
| 运行日志里的记录不见了 / 重启后日志一片空白 | v1.2.0 起日志会写进数据目录的 `app.log`（超过 2MB 自动轮转，保留一份 `app.log.1`），重启后界面上会回填上次最近 100 行，每行前面带时间。要翻更早的记录，去「文件管理」里打开 `data/app.log` |
| 后台顶上出现红条「配置文件不见了，已从上次的备份自动恢复」 | 数据目录里的 `config.json` 曾经消失（升级、清理脚本或误删），程序用备份顶上来了。**红条分两种**：说「配置文件不见了」的是用同目录的 `config.json.bak` 恢复的；说「升级时数据目录被整个删掉了」的是连 `.bak` 都没了、靠 `cf-ddns-sidecar-backup` 里那份救回来的，红条上会写出具体路径。**这时先别急着用**：逐项核对 AdGuard 地址、要加速的域名、DDNS 服务商和密钥是否完整，确认后点一次「保存全部设置」，红条才会消失。缺的部分重新填一遍。**v1.4.0 起新装的不会再因为它自己升级而出现这条**（正本已经搬出 `/var/apps`），出现就说明数据目录真的被外部删过 |
| 升级完发现配置空了，红条也没出现 | 说明备份目录里没有可用的备份。**v1.4.0 起这种情况基本不可能再出现**：数据本身已经不在 `/var/apps` 里，平台升级删不到它；万一真的空了，v1.3.2 那套「程序每次保存都自己备一份」还在兜着。想确认状态看运行日志第一屏，会有「数据目录已搬到存储卷：…」和「备份目录 … 可用：共 N 份，最新 …」两行。真要救场就用「备份与恢复 → 从文件恢复」手动导入 `config.json`，或者从之前导出的 json 恢复 |
| 重装、换 NAS 后不想再手抄一遍设置 | 用「备份与恢复」：旧机器上点「导出配置文件」把 json 存好，新机器装好打开后台，在同一处点「从文件恢复」上传即可。文件里带 AdGuard 密码和各家的密钥，**当密码一样保管**；后台登录密码不在里面（新机器用安装时设的那个） |
| 点「导出配置文件」浏览器没反应 | 飞牛桌面把后台嵌在 iframe 里，个别浏览器会拦下载。导出后页面下方会出现一段文本框，点一下全选、复制，粘到记事本里存成 `.json` 文件，效果一样 |
| 填了密钥，怎么知道填对没有 | 域名解析卡片里点「测试密钥」。三种结果：① 提示「密钥可用」——就成了；② 提示里带「看着像密钥不对或没有改解析的权限」——改密钥或去服务商加权限；③ 带「连不上服务商」——是 NAS 的外网出口问题，跟密钥无关。它测的是**已保存**的值，改完要先点「保存全部设置」 |
| 想立刻把 IP 推上去，不想等下一个周期 | 点「立即更新一次」。前提是已经测出过最优 IP；没测过它会提示你先点「立即测速」（空 IP 写进解析会把域名打坏，所以宁可拒绝） |
| 「下次测速」显示「未开启」或「—」 | 「未开启」= 间隔填的是 0，只在手动点「立即测速」时才跑；「—」= 程序刚起来还没算出来，等两秒刷新即可。改了间隔后这个时间会立刻重算，不用重启 |
| 上面显示「上次结果：失败」 | 鼠标往下看运行日志，最后几行有具体原因。测速失败已经会自动重试一次（等 10 秒），所以这里的「失败」是重试之后仍然失败。连续失败次数会一起显示 |
| AdGuard 里我自己加的重写记录不见了 | 每次测速都是「清空整张表再重建」，只保留「要加速的域名 → 当前最优 IP」这一批。动手前可以先点 AdGuard 卡片里的「看看现在写了哪几条」，黄色标记的就是下次会被清掉的。需要长期保留的记录，别放在这张表里 |
| 改了 TTL，为什么外面查到的还是旧 IP | TTL 就是「让全世界缓存多久」的意思，改小了不代表已经缓存出去的立刻失效，得等旧的那一轮过期。急着验证就别看本机缓存——用一个没查过这个域名的网络（比如手机切到流量）去查 |
| 开了云朵之后，「测试密钥」显示指向的不是最优 IP | 这是正常的。云朵一开，解析结果由 Cloudflare 接管，指向的是它的边缘节点，你填的优选 IP 变成了「源站地址」。想恢复成直连优选 IP，把云朵关掉再点「立即更新一次」 |
| 我把「同步几条 IP」从 5 改成 2，域名下怎么还有 5 条 | 改完要先点「保存全部设置」，再点「立即更新一次」。少了这一步只是把设置存起来，解析那边还没动。另外「立即更新一次」用的是上次测速的排名，不需要重新测速 |
| 填了 5 条，为什么感觉有的访问还是不快 | 多条 A 记录不是「都走最快的」，访问者是**随机挑一条**。填 5 条意味着只有约 1/5 的访问用到最快的那个，其余落到慢一点的。想要稳就填 1；填 2～3 是拿一点速度换「一条挂了还有备胎」，再往上基本只剩缺点 |
| 我以前手工加的那条 A 记录被动过 / 不见了 | 是故意的：「同步几条 IP」是「对齐」，填几条这个域名下就只留几条，多出来的同名 A 记录会被删。测不出 IP 的时候不会删任何东西。不想被动就先把那条记录挪到**别的子域名**上 |
| 填了 0 或者空着，会怎样 | 按 1 条处理（只写最快那条），行为和旧版完全一样。允许范围是 1–20，填超出范围会提示「请填 1 到 20 之间的整数」 |

## 开发者

```bash
docker build -t cf-ddns-sidecar:dev .
docker run --rm --network host -v $PWD/data:/app/data cf-ddns-sidecar:dev
```

端口由数据目录里 `ddns.env` 的 `CFDDNS_PORT` 决定（默认 8080），
所以用 host 网络而不是 `-p` 映射——改端口不用重建容器。

目录结构：

```
├── main.go              入口
├── config/              统一配置（config.json + ddns.env）
├── engine/              测速引擎调用（封装 cfnb）
├── dns/                 AdGuard Home 写入
├── ddns/                四家 DNS 服务商适配
├── web/                 后台服务 + 单页前端（go:embed，无需 Node 构建）
├── third_party/cfnb/    测速引擎（MIT，含一处本地补丁）
└── fpk/                 飞牛 FPK 打包模板
```

发布：打 tag 推送（`git tag v1.1.0 && git push origin v1.1.0`），
GitHub Actions 自动构建 amd64/arm64 镜像推 DockerHub，并用 fnpack 打出 `.fpk` 传到 Release。
