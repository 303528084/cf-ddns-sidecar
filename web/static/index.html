域名解析（DDNS）

把最优 IP 写到你的域名
密钥保存在数据目录的 ddns.env 里，留空表示不修改已保存的值。
按测速排名从优到劣，写前几条。填 1 = 只写最快那条（和以前一样）。
留 0 = 用各家的默认值（Cloudflare 自动、DNSPod 600、华为云 300、阿里云账号默认）。 填了之后，改了 IP 别人要等这么久才拿到新的；填太小有些免费版会直接拒绝（阿里云免费版要求 ≥600）。
填几条，这个域名下就只留几条。其他同名的 A 记录（包括你以前手工加的）会被删掉， 否则会一直留着已经失效的旧 IP。测不出 IP 的时候一条都不会删。
另外，多条 A 记录不是「都用最快那条」，访问者是随机挑一条。所以 2～3 条是「一条挂了还有备胎」， 填到 5 条以上，大部分访问反而会落到不是最快的那些上面。
一般不要开。开了之后域名会解析到 Cloudflare 的节点，不再指向你测出来的最优 IP， DDNS 就白做了——只有在你想隐藏源站、并且不需要优选 IP 的时候才开。
这两个按钮用的是已经保存的设置——刚改完的密钥请先点上方的「保存全部设置」，否则测的还是旧的。
「测试密钥」只读：只确认密钥能不能用、能不能查到这个域名、现在指向哪里，不会改动你的解析。
「立即更新一次」才会真的把当前最优 IP 写进去，不用等下一个测速周期。

测速设置

多久跑一次、跑多少候选、从哪些来源取 IP
间隔填 0 表示不自动测速，只在点「立即测速」时执行。
候选数越大，失败时可切换的备选越多。
每行一条，三种写法都认：IP 段（104.16.0.0/13）、单个 IP（1.2.3.4）、链接（https://…）。 填了之后就只用这些——不再叠加 Cloudflare 官方段，也不再拉内置的两个外部聚合源；想恢复原来的行为，把这里清空保存即可。
为什么需要它：官方那 15 个段里 104.16 / 104.24 / 172.64 三块占绝大多数，优选结果会明显往这几段集中。
